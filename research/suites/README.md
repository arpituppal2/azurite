# Azurite suite manifests

Two materialised suites, both generated by `scripts/build_context_suite.py`:

- [`dev_suite.json`](dev_suite.json) — compact, used for architecture and
  context-scaling decisions.
- [`locked_suite.json`](locked_suite.json) — broader, sealed, not opened by the
  context-scaling experiment.

They are not leaderboards. They are row-level provenance records: every task has
a local path, a source, a licence status, train/test row digests, and file
hashes. `dev_items.jsonl` and `locked_items.jsonl` record the per-row identity
(`context` hash, `question` hash, label). Rebuilding a task without the same
rows changes the digest.

## Compact dev suite

| task | family | weight | train / test | context p50 |
|---|---|---:|---:|---:|
| `banking77_ctx` | classification | 0.20 | 2,500 / 750 | 47 B |
| `clinc_oos_ctx` | classification | 0.20 | 2,500 / 750 | 38 B |
| `boolq_ctx` | document-grounded | 0.20 | 2,500 / 750 | 556 B |
| `squad2_answerability_ctx` | document-grounded + abstention | 0.20 | 2,500 / 750 | 768 B |
| `contract_nli_ctx` | policy / rule-conditioned | 0.20 | 2,499 / 748 | 10,821 B |

- Built **only from training splits**. The official test/validation rows are
  reserved for the locked suite.
- Rows are grouped by document before splitting, so two questions over one
  passage never cross the boundary. The measured context overlap is **0** for
  all five tasks.
- Banking77 and CLINC150 are short-context controls: their p90 contexts are
  117 B and 58 B, so a longer window cannot add information.
- ContractNLI is a long-document task; every tested window below 8k is a
  partial-context row.
- No dataset exceeds 25% of the dev suite; the actual weight is 20%.

## Split roles and calibration

| role | rows | permitted use |
|---|---:|---|
| **train** | 2,499–2,500 per task | fit the model or head |
| **dev** | 748–750 per task | architecture, hyper-parameter, and protocol decisions |
| **calibration** | **not materialised** | fit thresholds or abstention policy; must be disjoint from train, dev, and locked |
| **final** | locked suite | one evaluation after the method is frozen |

The context-scaling heads use argmax; no calibration or abstention threshold was
fitted, so the v1 dev results consume no calibration partition. Do **not** fit a
threshold on the v1 dev test: it has been inspected for the context result and
is now legacy development evidence. Any calibration run requires a new suite
version with a calibration partition carved before training. The locked suite
can never supply calibration rows.

## Broader locked suite

Twelve tasks, 493–500 rows each, equal task weights (8.33%). Nine are the
existing local suite; three are the new document/policy tasks. The suite is
broader than dev but **not complete across six families**:

- present: classification, document-grounded, document-grounded + abstention,
  policy / rule-conditioned;
- missing: tool/action selection + abstention, relevance/preference/ordinal,
  multimodal visual.

The missing families are recorded as blocked, not replaced by toy tasks.

**It is a procedural lock, not an untouched-data claim.** Nine of the twelve
tasks were inspected by earlier work; `previously_inspected` marks them. The
lock starts 2026-10-30. No threshold, prompt, architecture, or hyper-parameter
may be selected on these rows.

**Document-disjointness was checked, not assumed.** BoolQ's official validation
split shares 45 passages with its train split. Those 45 passages are excluded
from the locked BoolQ sample; the verify script checks the remaining overlap is
zero. The same check covers SQuAD 2.0, ContractNLI, Banking77, and CLINC150.

Five tasks are marked `product_admissible: false` because their licences are
unresolved (`ag_news`, `emotion`, `xnli_en`, `language_id`, and
`financial_phrasebank`). They remain in the research suite and cannot enter a
shipped product until resolved.

## Comparator labels

The suite files do not contain Jev results. The registry distinguishes:

- **published_reference** — a vendor/third-party number, not rerun here;
- **local_reconstruction** — a stored public per-example vector, not a live
  call (Banking77 0.924 only);
- **reproduced_live** — same rows, same pinned version, live call; **zero** in
  this checkout.

Do not call the Banking77 0.924 point a reproduced Jev run.

## Rebuild and verify

```bash
.venv/bin/python scripts/build_context_suite.py
.venv/bin/python scripts/verify_suites.py
```

The builder refuses to overwrite existing task directories. Rebuilding is a
new artifact with new hashes, not an edit to the frozen manifest.
